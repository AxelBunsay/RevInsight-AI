# Fixed Issues

| File or area | What was wrong | Change made |
|---|---|---|
| `backend/controllers/paymentController.js` | Webhook and legacy payment-intent handlers remained. | Deleted the obsolete controller. |
| `backend/routes/payment.js` | Exposed obsolete payment-intent endpoints. | Deleted the route module. |
| `backend/server.js` | Required the payment route/controller and mounted the webhook and legacy API. | Removed both requires and the obsolete mounts. |
| `backend/package.json`, `backend/package-lock.json` | The removed payment provider remained a backend dependency. | Removed the dependency and updated the lockfile through npm. |
| `frontend/src/services/api.js` | Exposed obsolete `createPaymentIntent` and `confirmPayment` methods. | Removed both methods. |
| `backend/.env.example` | Runtime configuration referenced `NODE_ENV` and `RENDER_EXTERNAL_URL`, but the example omitted those names. | Added `NODE_ENV=development` and an empty optional `RENDER_EXTERNAL_URL` entry. No values were copied from `.env`. |
| `backend/server.js`, `backend/app.js` | Express construction and route wiring were coupled to database connection, bootstrap, expiry timers, and listening, preventing safe in-process API integration tests. | Moved Express app construction and middleware/routes into `app.js`; `server.js` still imports the app, connects MongoDB, bootstraps admin/settings, starts the existing 15-minute expiry timer, and listens. The `.env` is not loaded by `app.js`. |
| `backend/middleware/loginRateLimit.js`, `backend/routes/chat.js`, `backend/app.js` | Rate limiters would interfere with repeatable integration requests. | Made the global, login, and chat limiters pass through only when `NODE_ENV === 'test'`; non-test configuration is unchanged. |
| `backend/package.json`, `backend/package-lock.json` | HTTP integration test client and replica-set test database dependencies were not installed. | Added `supertest` and `mongodb-memory-server` as development dependencies. |
| `backend/tests/integration/helpers/index.js`, `backend/vitest.config.js`, `.gitignore` | No isolated transactional integration-test harness existed, and MongoDB startup used an unpinned default binary/short launch timeout. | Added a MongoDB 7.0.14 single-node replica-set harness with a 120-second launch timeout, project-local ignored binary cache, mocked Cloudinary, fixtures/token helpers, and 180-second Vitest hook/test timeouts. The initial unpinned launch timeout failure was resolved by the pinned configuration. |
| `backend/controllers/adminControllers/dashboardController.js` | Projected revenue included the currently active quarter and generated a projection even with fewer than five completed quarters. | Excluded the current Manila quarter, required five completed quarter buckets, and returned `insufficientData`, `availableQuarters`, and an empty projection until enough history exists. |
| `backend/tests/integration/helpers/index.js`, `backend/tests/integration/revenue.test.js` | The integration harness did not export the legacy `Order` model needed for end-to-end revenue-source coverage. | Exported the model and added four HTTP integration scenarios covering consistency across analytics endpoints, Manila date boundaries, forfeitures, and completed-quarter projection history. |
| `backend/tests/integration/security.test.js` | The account-role matrix, deleted-token behavior, active-record deletion guards, and historical anonymization were not covered at the API integration layer. | Added five Supertest scenarios against the in-memory replica set, including multiple routes per role and persistence checks for unchanged financial amounts and dates. |
| `backend/package-lock.json` | Initial `npm audit` found high-severity advisories in body-parser and multer, plus moderate advisories in ip-address and nodemailer. The affected packages were resolved through Express, express-rate-limit, and direct dependencies. | Ran `npm audit fix` without `--force`. Compatible resolutions updated body-parser to 2.4.0, ip-address to 10.7.5, multer to 2.5.0, and nodemailer to 10.2.1; final backend audit reports zero vulnerabilities. |
| `frontend/package-lock.json` | Initial `npm audit` found high-severity advisories in source-map-js, Vite, and Zod (the latter two are in the development toolchain). | Ran `npm audit fix` without `--force`. Compatible resolutions updated source-map-js to 1.2.2, Vite to 6.4.5, and Zod to 4.6.7; final frontend audit reports zero vulnerabilities. |
| `frontend/src` unused-file cleanup | Fourteen requested files had no external static/dynamic import, symbol, or CSS `@import` references. AdminLayout directly imports the stylesheet constituents, while the admin reservations route redirects instead of rendering the obsolete page. | Deleted the unused App.css, legacy Orders alias/data/styles, three unused admin layout components, obsolete admin Reservations page and aggregate stylesheet, unused logo assets, and Header component. Kept the routed customer Reservations page, `main.jsx`, and test files. |
| `docs/test-evidence/summary.md` | The evidence report did not include the latest dependency audit and cleanup results. | Added the initial audit finding inventory with severity, direct/indirect classification and usage notes; recorded remediation, final audit state, dead-file search outcome, and latest validation results. |
| Post-remediation validation | Dependency lockfile updates and file removals required regression checks. | Backend: 18 files / 96 tests passed. Frontend: 2 files / 7 tests passed, lint passed, and production build passed (118 modules). |

| Integration test fixture/assertion | Fixture emails used a top-level domain rejected by the existing User schema; one test expected `completedAt` in a mechanic response that does not serialize that field. | Corrected fixture emails to valid `.com` addresses and asserted the persisted booking timestamp instead. No production behavior changes were required by the integration failures. |

No application behavior bug was exposed by the integration suite. The first `npm install` invocation was run from the repository root, which has no `package.json`; it was rerun successfully in `backend`, and the incidental empty root lockfile was removed.
